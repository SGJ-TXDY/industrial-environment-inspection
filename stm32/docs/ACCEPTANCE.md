# 验收记录与步骤

## 自动化验收

- run_host_tests.py：应全部通过，使用纯 C 核心和 i.MX6ULL 原 inspect.c，不改接收端实现。
- 49/50/51 ms 严格空档边界、正常帧重复、残次锁定、低置信度、空档被不确定帧打断、丢帧、时钟/序号回绕、故障只提交一次。
- 正常 97% 序号 1 = 210#0200612501000000；残次 88% 序号 2 = 210#0201582502000000；运行心跳序号 2 = 211#0200250002000000。
- 10 分钟虚拟回放：12000 样本、600 件、480 正常、120 残次、其中 60 需复核；接收器 MISSED/DUP/BAD 均 0。
- HAL 故障注入：入队不算发送完成、FIFO 满、200 ms 无 ACK、Bus-off、初始化时钟失败、错误时钟不可用、RNG 故障、会话稳定、128 条队列溢出、恢复顺序及模拟标志。
- build_firmware.py：三套应用配置与 FSBL Release 均应成功编译链接；日志位于 build，各配置保留独立结果。

## 上板验收（未连接硬件时不得填写通过）

1. 确认板卡型号与 P10 跳线、CAN 终端。两端 500 kbit/s。先启动接收端。
2. Simulation RAM 调试或 SimulationFlash 上电：摄像头画面正常、始终显示 SIMULATION、概率按节拍变化。
3. 20 FPS 摄像头采集和模拟概率分别计数，不能用模拟 FPS 代替真实识别 FPS。
4. 冷启动后运行 600 件，比较两端总数和序号；REVIEW 只在 STM32 本地单独显示。
5. 断开 CAN 接收端，验证 MCU 不因发送等待卡住；记录失败；恢复后按顺序补发，BACKLOG 回落；断线期间最多缓存 128 件，超过容量 LOST 增加；相邻重复只计一次。
6. 断开/遮断摄像头数据，使其 250 ms 无帧，验证 CAMERA FAULT 心跳、在途产品保守结束且仅一次。
7. Production 未接真实模型时：MODEL FAULT，检测序号 0，禁止模拟回退。
8. 连续重启并比较摄像头、外部存储及 FSBL 上电行为。验证会话变化时新 seq=1 能接收，即使旧会话最后也是 1；CAN 断线恢复期间会话保持不变。随机 8 位会话仍可能碰撞。

## 真实模型性能与精度

接入真实模型后，使用真实摄像头、LCD、CAN 同时运行至少 10 分钟。

- 有效识别平均 ≥19.5 FPS，最长有效帧间隔 ≤75 ms。
- 帧完成至结果可用 P95 ≤50 ms，串口输出 latency 和 p95；平均 FPS 可用 processed×1000/age_ms 计算；P95 使用累计直方图，250 ms 桶包含所有更高值。
- 记录 NPU 时间、最长帧间隔、采集丢帧、推理忙丢弃数、CAN 完成/失败数。
- 在单件可见约 700 ms、空档约 300 ms 场景下，每件只提交一次。
- 使用人工标注结果统计正常误判、残次漏检、需复核比例；模型准确率阈值由实际质检要求确定，不能由模拟测试替代。

物理误检、漏检与软件计数错误分别记录。出现相邻产品重叠或空档不够时，本版不承诺实例分离。
