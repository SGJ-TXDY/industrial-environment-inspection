# STM32N647 → IMX6ULL 检测结果 CAN 协议（版本 2）

本协议由本工程定义，STM32 固件需按此实现；改动时同步修改 `app/inspect.h`、`app/inspect.c` 和本文件。

版本 2 在版本 1 的保留字节中加入 **启动会话编号**。IMX6ULL 同时接受版本 1 和版本 2 的报文，STM32 固件可以分开升级。

## 总线参数

- 经典 CAN 2.0A（非 CAN FD 帧），标准 11 位 ID，数据帧，DLC 固定为 8。
- 默认 500 kbit/s，由板端 `/etc/default/sensor-dashboard` 的 `CAN_BITRATE` 设置，两端必须一致。
- 多字节字段为小端序。保留字节发送 0，接收端忽略。
- IMX6ULL 只接收、不发送数据帧；FlexCAN 控制器会自动为 STM32 的报文应答（ACK）。
  总线上若只有 STM32 一个节点且 IMX6ULL 未上电或未启动，STM32 会因无应答而不断重发并进入错误被动状态。

## 启动会话编号

一件产品由 **会话编号 + 检测序号** 唯一确定，不能只看序号：STM32 重启后序号从 1 重新开始，如果上一次运行的最后一件也恰好是 1，只看序号会把新的第 1 件当成重发丢掉。

- STM32 每次上电（或复位）后选一个 1–255 的会话编号，整个运行期间不变，写入每个结果帧和心跳帧。0 保留，表示“没有会话编号”（版本 1）。
- 推荐用硬件随机数发生器（RNG）产生；如果有掉电保持的存储（备份寄存器、Flash），可以改为每次启动加 1、跳过 0，这样相邻两次启动一定不同。
- 用随机数时，相邻两次启动抽到相同编号的概率为 1/255。此时接收端退回到版本 1 的规则（序号变小视为重启），只有在旧会话最后一件的序号与新会话第一件相同时才会误判，概率很低。

## 0x210 检测结果（每检测一件发送一帧）

| 字节 | 类型 | 内容 |
|---:|---|---|
| 0 | u8 | 协议版本：`2`（版本 1 仍被接受） |
| 1 | u8 | 结果：`0` 正常成品，`1` 残次品；其他值丢弃 |
| 2 | u8 | 置信度 0–100（%）；`0xFF` 表示不提供；101–254 丢弃 |
| 3 | u8 | 版本 2：启动会话编号 1–255，0 视为格式错误；版本 1：保留，忽略 |
| 4–7 | u32 | 检测序号。每个会话从 1 开始，每检测一件加 1 |

接收端处理（按收到的上一件比较）：

- **会话编号不同**：STM32 重启了（计入“重启”）。新会话从 1 开始编号，所以新会话的第一件若是 n，前面 n−1 件计入“丢失”。
- **会话相同、序号相同**：重发，丢弃且不重复计数（计入“重发”）。
- **会话相同、序号大 n（n > 1）**：中间 n−1 件计入“丢失”。
- **会话相同、序号变小或跳变超过 10000**：视为重启或计数回绕（计入“重启”），不计丢失。版本 1 报文没有会话编号，只能按这条规则判断。
- IMX6ULL 启动后收到的第一帧只用于同步，不计算之前的丢失。
- 计数从应用启动开始累计，应用重启后清零。数据库 `inspection` 表与 MQTT 上传都记录 `session` 和 `seq`（版本 1 记为 NULL / null）。

## 0x211 心跳（每 1 秒一帧，即使没有产品经过也要发送）

| 字节 | 类型 | 内容 |
|---:|---|---|
| 0 | u8 | 协议版本：`2`（版本 1 仍被接受） |
| 1 | u8 | STM32 状态：`0` 运行中，`1` 空闲，`2` 摄像头故障，`3` 模型故障 |
| 2 | u8 | 版本 2：启动会话编号（与结果帧相同）；版本 1：保留 |
| 3 | u8 | 状态标志：bit 0 = 模拟模式，0 = 生产；其他位保留。当前 Linux 忽略此字段 |
| 4–7 | u32 | 本会话至今发出的最后一个检测序号，用于与界面的计数核对 |

超过 3 秒既没有心跳也没有结果，界面显示“STM32：离线（无心跳）”。

## 示例（can-utils `cansend` 格式）

```sh
cansend can0 210#0200612501000000   # 会话 0x25=37，第 1 件，正常，置信度 97%
cansend can0 210#0201582502000000   # 会话 37，第 2 件，残次品，置信度 88%
cansend can0 211#0200250002000000   # 心跳：运行中，会话 37，已发出 2 件
# STM32 重启后抽到会话 0x2A=42，第 1 件仍是序号 1：按新会话正常接收，不会被当成重发
cansend can0 210#02005F2A01000000   # 置信度 95%
```

STM32 端参考实现见 `docs/stm32_can_sender.c`。

## 本 STM32 发送端的补发行为

- 每次启动用硬件 RNG 产生 1..255 的会话，CAN 控制器重初始化不更换会话；RNG 失败时不发送无效会话报文，定期重试并累计 session_failed。
- 检测结果进入 128 件 RAM 队列；返回成功表示保存入队。队满丢最新结果，LOST 增加。重启丢失未完成缓存。
- 同时只有一件结果在硬件发送中，检测结果按序提交。200 ms 超时、bus-off 或 HAL 状态故障时保留队首，停止控制器后等待 1 s 重建并重发。
- 发送完成后才弹出队首；未知结果可能被连续重复发送，接收端按同一会话＋序号去重。硬件完成与 Linux 落库之间没有应用层 ACK，不能保证端到端不丢失。
- 心跳最后序号表示已生成的最后一件，即使尚在缓存或因满队列被丢弃；这不是已成功送达数量。补发记录的 Linux 时间是接收时间，不是原始检测时间。
- 模拟模式标记仅位于心跳 byte 3，逐件结果帧没有模式字段，当前接收端不隔离模拟记录。不要混用演示数据库和生产数据库。
